## 已发现的审查风险

- **安装保护回归：已修复。** 插件管理单测断言安装命令包含 `--ignore-scripts`；这不是第三方插件执行安全的完整证明。
- **会话删除：待核对并发。** Web 在多个异步服务检查后删除，检查与删除之间没有统一互斥。JSONL 备份重命名与其他存储的物理删除也不是同一种恢复能力。
- **OAuth：待完善边界。** 登录状态的 configured 使用 checkAuth，可能包含环境凭据，不能直接等同“可退出的已登录账号”；真实授权回调没有端到端证明。登录流满额时同供应商替换、过期 ID 的 HTTP 错误、前端登出异常和中英文文案继续检查。
- **变更耦合：必须按 hunk 拆。** app.js（+2624/-105）、server.ts（+2584/-77）、client-runtime.js（+1214/-18）、dsh-compat/index.ts（+3769/-138）混合多个功能。把一个目录提交完不能证明该提交功能完整。
- **锁文件：需要依赖审计。** 当前锁文件 +10023/-1205；不能只因能安装就确认全部新增依赖必要。根 workspace 的 build allowlist 与插件安装的脚本禁用是不同范围，分别核对。

1. 仓库卫生：忽略已确认生成物；不带业务实现或版本号。

4. 凭据与供应商：目录/原生协议和 OAuth 分开；OAuth 未通过门槛不跟随提交。
5. 原生功能插件：按 Team/任务、目标/计划、终端/LSP、网络等功能分别提交，不以全 plugins 目录为单位。
6. DSH 桥接与插件生命周期：只包含已验证的兼容服务；安装安全修复可单独拆 hunk。
7. Web API 与 UI：删除、皮肤、设置、输入区等分别提交；共享文件按 hunk 拆分，测试随行。
8. SDK、ACP、RPC：分别验证各入口与独立打包；文档随对应交付。
9. CI、发布脚本、统一补丁版本与发布说明：最后独立处理。
