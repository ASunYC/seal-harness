# 对标 Octop Enterprise 的功能差距与补齐规划

## Goal

对标本机 Octop Enterprise，整理 Seal Harness 的功能差距和补齐顺序，为后续逐阶段实现提供依据。本轮交付源码与文档盘点，不把整个企业平台改造隐含为本轮实现范围。

## Background

- 用户要求：“把 seal-harness 的功能补齐。对标 Octop-Enterprise 中有的，整理下”。
- 对比日期：2026-10-25；Seal 基线 `0214127e2d2c18fd17a134a0f3b616fa3182f5ad`；Octop 基线 `469d13fe7db6850d781b9d5695ed796ffa2aa3ed`。
- Seal 当前为本地 Desktop + DSH 插件组合；Octop Enterprise 为企业服务器 + 员工本机执行客户端。服务端与客户端能力不能混算。
- 详细证据与功能矩阵见 [research/feature-gap.md](research/feature-gap.md)。

## Requirements

- R1：区分已装配、部分具备、产品缺失、企业服务端能力及尚待实测；源码存在不等于端到端可用。
- R2：核对专家、技能、连接器、知识库、记忆、文件成果、自动化、语音、媒体、浏览器、编程工具、企业协作、治理和运维。
- R3：给出阶段顺序和可验证结果；对齐用户价值，复用 DSH 公开服务、slot、bundle、profile。
- R4：记录既有契约冲突：知识库/项目/远端身份此前已移除；恢复这些功能须先更新对应产品契约与迁移设计。
- R5：保留独立品牌、更新渠道、Node/Yarn 约束、只读子模块和第三方许可，不修改 Octop 源码。

## Acceptance Criteria

- [x] 功能矩阵覆盖 R2，并提供双方可定位的源码或文档证据。
- [x] 不把 Seal 已有生图、语音输入、浏览器、终端、工作流、Agent 团队误报为完全缺失。
- [x] 明确系统专家、空间、双任务系统与 README 漂移。
- [x] 区分桌面补齐与企业平台扩展，记录建议顺序及验收结果。
- [x] 标明静态盘点范围，不宣称 UI、真实模型、第三方服务、安装或跨平台验证通过。

## Out of Scope

本轮不修改运行时代码、数据库、版本、构建配置或既有规范，不推送、发布，不启动图形应用。用户已授权提交本次走查规划资料。后续具体实现阶段仍需细化设计、执行清单与检查。
