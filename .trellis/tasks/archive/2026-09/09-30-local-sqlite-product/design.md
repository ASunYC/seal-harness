# 设计草案：本地身份与单库数据

## 已确认的技术边界

- 产品仍使用 DSH Desktop 的 Cordis bundle/Profile、Beta Electron Host 与原生会话 UI；`deepseek-harness/` 固定子模块保持只读。
- `knowledge` 和产品 `agents` 两个插件从产品装配及资源导航移除。产品 AgentRegistry 覆盖随之撤销，让 DSH 默认 `agent` 恢复，普通对话仍能运行。
- 用户、项目、专家、技能在同一个 `~/.seal-harness/seal-harness.sqlite` 文件内用不同表保存，显式 `DSH_HOME` 可改变基础路径。库中按用户 ID 隔离行；启用外键与 schema 版本迁移。
- 优先用项目已在用的 `node:sqlite`，不另引入原生 SQLite 扩展。Node 22.19+ 与当前 Node 24 均可加载该模块。
- 数据库服务是产品自有 Host 插件，负责单连接和建表；身份插件负责注册/登录/退出和当前用户；项目、专家、技能复用数据库服务，不直接各开数据库文件。
- 旧远端身份、SSO 和企微处理器与界面移除。登录页重新设计，使用 `assets/icons/128x128.png` 派生的小海豹资源；现有原生图标与 LFS provenance 不改。

## 默认实施选择（用户回复后可调整）

1. 本机账号密码，首次创建管理员；密码用随机盐和 `scrypt` 派生，仅在 Host 校验。会话保存在 Host 内存，应用重启需重新登录。
2. 旧专家/技能/项目数据一次性事务导入并保留原文件，失败回滚，不自动删除旧文件。
3. 项目页先保留本地项目 CRUD、工作目录和原生对话；远端协作页签停用并明确说明，不能继续请求来源服务。全部八页签离线重建留待明确要求。

## 保持的接口与风险

维持现有 Connection RPC 信封和用户插件订阅接口，改变其实现而不改 DSH 内核。SQLite 只允许 Host 访问，Client 不接收密码哈希和原始数据库路径。项目页的现有 Stratex 协作处理器强依赖网络，必须明确替换或停用，不能只把项目标题写进 SQLite 而保留后台远端请求。专家与技能目前有 ZIP/文件副本；数据库应成为其正式数据源，运行时需要的资源可按现有 DSH 插件接口短期物化，但不能把物化文件当唯一权威数据。

质量验证包含真实 SQLite 建表、事务、重启持久化、用户隔离、删除、错误路径、产品 Profile 启动以及 Windows/macOS/Linux 路径处理。图形、原生打包和升级分别记录实测范围。
