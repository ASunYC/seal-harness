# 设计

## UI 与数据边界

专家 Host 已以 `seal-harness.sqlite` 的 `experts` / `expert_state` 表作为每位本地用户的权威数据，缓存目录可重建。继续使用现有 `experts/create` 的验证与保存流程，不另建数据库或模型输出文件作为第二来源。系统页当前不伪造专家；个人页使用当前账号的 `experts/list`。

专家 Client 删除 `SyncRefresh`、“我的专家”、已安装轨道、公开/授权目录和整页 `ExpertEditor` 创建/编辑路径。保留导入、详情、启停、版本和对话使用。创建按钮调用现有会话服务：新建当前/默认工作区会话，写入可编辑模板草稿，再打开会话。不能直接提交草稿或破坏已有会话内容。

## 模型保存通路

专家 Host 注册模型可调用的 `create_expert` 与可用能力查询工具。模型从用户发送的模板整理名称、角色、工作方式及可选技能/连接器引用；工具对名称、模型选择、能力引用和当前本机身份进行校验，调用现有串行 `experts/create` 保存。工具返回可核对的专家标识与版本；只有保存成功才能提示“专家已创建完成”。缺少模型配置或能力时返回明确错误，模型不得假称成功。

本次保留 ZIP/目录导入为个人专家。旧手工编辑表单从产品页面与入口删除；修改配置按钮不再跳转到它。未来系统内置专家再设计产品资源包与账号可见性，不在本轮伪造卡片。
