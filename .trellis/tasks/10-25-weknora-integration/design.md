# 设计

WeKnora 使用工作区官方 Compose 的 0.8.3 镜像运行，前端、应用、文档解析、PostgreSQL 和 Redis 属于同一服务栈。真实数据留在 Docker 卷；环境密钥使用仓库忽略的 `.env`。镜像仓库只保存无数据的应用镜像。

Seal 的 `seal-harness-desktop/plugins/weknora` 保留官方插件实现，将它编入现有本地插件数组与 Cordis patch。插件使用 `WEKNORA_BASE_URL` 和 `WEKNORA_API_KEY` 读取本地部署，工具注册由 DSH 的 `ctx.tools` 完成。避免将密钥写进跟踪文件；现有 Profile 装配验证覆盖加载。第三方源码在插件目录注明来源、commit、许可。若官方插件与当前 DSH 工具契约不兼容，只做必要的产品侧适配并记录差异。

WeKnora 文档导入与索引通过其自身 API/UI 进行；Seal 不复制知识库数据和检索引擎。检索工具结果应保持文档来源。阿里云目标使用用户已打开的华北 2 个人版实例，在既有命名空间下新建或复用专用私有镜像仓库，以固定版本标签推送。

回退：停止 Compose 服务但保留卷；移除产品插件装配即可恢复原产品行为；镜像仓库中的固定版本标签可独立删除。不得自动删除数据卷或用户仓库。
