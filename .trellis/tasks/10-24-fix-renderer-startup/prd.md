# 修复升级后桌面前端启动超时

## 需求与现象
原有 desktop Profile 在 DSH 0.2.1-rc.2 升级后进入恢复页，提示 Renderer 未在 30000ms 内报告健康。用户要求可正常启动当前 Seal Harness。

## 边界
先捕获真实窗口的客户端异常、网络失败与启动健康协议，定位最小行为缺口。优先修复产品装配；只有证据确认共享 Desktop 行为有缺口时才修改 Beta 并同步 Stable。保留账号、工作区、会话、凭据和现有插件数据，不以重置 Profile、禁用插件或无依据延长超时掩盖原因。不更新只读上游子模块，不改变发布版本或推送。

## 验收
- 说明真实根因及相应证据。
- 相关回归、类型/构建检查通过。
- 使用用户现有 Profile、产品默认 Host 模式启动，健康事件为 healthy，主界面可用。

## 执行
1. 采集 CDP 与日志，确定失败层。
2. 记录具体修改边界，完成最小修复与回归。
3. 重建实际产品并启动验证。

## 定位与修改边界
- 真实原 Profile 的冷启动在 Renderer 计时开始约 35 秒后才完成页面初始载入；30 秒失败分支先关闭 Host，页面随后停在 Loading plugins。未捕获客户端异常或插件失败。
- 临时延长诊断窗口后，真实 Profile 成功提交 healthy；还原 30 秒后的验证耗时约 29 秒，也能 healthy，证明原预算没有冷启动余量，不能把超时解释为坏插件。
- 公开插件 API 不能设置原生主进程的启动健康截止时间。因此仅在现有 DesktopProductConfig 加可验证的 rendererBootTimeoutMs，产品选 90 秒，上游默认仍 30 秒；不改变健康协议、不跳过任何失败检测。
- 共享配置读取、原生默认值与相关测试 Beta 先改，再镜像 Stable；产品配置和构建契约记录行为。生成文件的诊断性 180 秒修改已恢复。

## 用户复测追加：会话创建失败
- 界面 healthy 后创建原生/决策会话仍报 playwright-mcp 初始连接失败。先前只验证了 Renderer 健康，未覆盖会话创建，验收不足。
- 增加验收：真实原 Profile 的新会话和决策会话可以创建，内置浏览器 MCP 能握手并注册工具；不禁用浏览器能力、不吞掉创建错误、不修改用户的模型供应商和凭据。
- 新版 Playwright MCP provider 以 process.execPath 启动 npm CLI；当前进程内 Host 的该路径是 Electron。先对比该命令的普通模式/Node 模式握手，确认后优先沿现有 Desktop 子进程边界修复，不改只读上游子模块。
- 实测同一命令的普通模式 6 秒后 Connection closed；子进程 Node 模式约 1 秒握手并返回 24 个浏览器工具。旧 0.1.7 补丁中已有相同兼容处理，升级到 rc.2 时遗漏了该叶子包补丁。
- 追加修改边界：移植该 0.2.1-rc.2 Yarn 补丁，更新根 resolution/lock；原始官方 tarball、Stable/Next 的 runtime pin 不变。现有 provider Config 不暴露命令/env 覆盖，不能仅靠公开产品插件配置解决。
- 产品 Profile 冒烟改用真正 Electron 的 Node 运行时，在清除父进程全局标志后创建 standard 会话并断言浏览器工具存在，以覆盖本次遗漏。共享冒烟脚本的可选验证分支同步两变体，产品只对 Beta 启用。保留已有 Creator、插件管理和两轮 HMR 检查。
- 冒烟引导另行隔离基础 DSH_HOME：产品 SQLite 不仅取决于临时 Profile，不能让新增会话测试读取真实账号数据库。此隔离只作用于测试子进程，结束后验证临时目录父路径再清理。
